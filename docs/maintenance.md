# 保守・公開の手順

## 初回公開

1. 会社Organizationの正確なログイン名、作成権限、公開対象の著作権を確認する。
2. この内容を`ai-tutor`というPublicリポジトリに登録する。READMEやLICENSEをGitHub側で自動追加しない（初期ファイルの衝突を防ぐ）。
3. Issuesを有効にし、まず`feedback`、`bug`、`enhancement`、`documentation`、`needs-reproduction`ラベルを作る。Issueフォームはラベルの存在に依存させていない。
4. GitHub Actionsを有効にし、`Validate / validate`が通ることを確認する。
5. 可能な範囲でmainへの直接pushを制限し、PRレビューとCIを使う。利用プランに応じた設定を選ぶ。
6. 実際のAIで評価シナリオを実行し、初回リリースの根拠を記録する。
7. `v0.1.0`タグとReleaseを作り、使い方・既知の制約・配布物へのリンクを掲載する。

公開先は[codeberry-dev/ai-tutor](https://github.com/codeberry-dev/ai-tutor)です。`VERSION`は初回候補の0.1.0で、Release公開は対話評価後に行います。現在の状態は[HANDOVER.md](../HANDOVER.md)を確認してください。

## Issue→改善→配布

- 報告を分類し、再現条件と利用版を確認する。
- 公開できる最小教材で再現する。顧客情報を取り寄せない。
- Issueに対応するPRを作り、仕様と関連文書を変更する。
- 配布物を再生成し、CIと該当する対話シナリオを確認する。
- マージ後にバージョンとCHANGELOGを更新し、再生成する。Releaseの変更点にIssue番号を記載する。
- 利用者が選べるようタグを保持し、更新を案内する。

## バージョンの目安

0.xの間は試行版として扱います。軽微な文言修正はpatch、教え方・モード・導入方式の追加や変更はminorを上げます。利用者が手順を変える必要がある場合は変更点を明記します。

## 今後の候補

実測が集まってから、時間指定の短縮モード、初心者／経験者の進行調整、英語対応、環境別の動作確認表を検討します。自動採点や顧客PRへの記載は前提にしません。
